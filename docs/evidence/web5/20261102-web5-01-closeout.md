## 3. Agreed consumer boundary and gate disposition

[ADR0015](https://github.com/chung6a8m/MyDmsVn/blob/3aed45a5116f8d45ce7bfe061dc7f996b125a05b/docs/adr/0015-web5-additive-recovery-boundary.md) is the owning backend decision. The implementer selected additive/schema013 based on source review within the requested closeout; this is not a claim that Owner separately chose a wire shape.

Additive preserves the strict literal `web4-v1` context with no extra fields, six mutation contracts and original protected status. Existing v1 intent bytes/fingerprint/raw buffers/CAS remain valid across client deployment; database epoch is not a bundle version. The future separate resolution surface must bind the original identity and stored-kind Write/Post grant, permit ordinary Read denial when the original grant remains valid, and retain original command outcomes (Sales Post version, Receipt Post no invented version). Current v1 CANCELLED maps to unavailable, never an unlock. A negative needs committed CANCELLED plus matching immutable operator audit under the same epoch/actor/key transaction fence. Browser/runtime cannot mint that authority; local certificate alone is insufficient. Local atomic CAS, retained raw draft, fresh authorized baseline and explicit new user intent precede any later mutation.

Schema013 is the selected append-only direction for atomic terminal audit and authority constraints. DDL, exact13 admission/grants/fingerprint, implementation and migration tests are NOT RUN. Old server binary/schema13 must reject startup; additive browser compatibility is not binary/schema compatibility. B02 still must publish exact route/method/headers/DTO/status/error mapping and new canonical corpus **before F02 fetch/decoder work**. A sample route is not a contract.
