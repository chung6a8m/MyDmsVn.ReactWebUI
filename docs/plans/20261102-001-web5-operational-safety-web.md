## 0. Product goals, exclusions and invariants

WEB4 delivered actor+epoch-scoped IndexedDB draft, immutable operation ID/frozen intent, protected readback and conservative UNKNOWN. Roadmap 05 adds browser-side **safe operator reconciliation**, conditional user-confirmed resend only after proven server fence, trustworthy full IIS staging and candidate-specific acceptance, without weakening local persistence/permissions/stock boundaries.

- Preserve React/TypeScript/Vite, default Tailwind CSS v4 + shadcn/ui Nova/Base UI (no Business Compact/font restyle), Zustand feature-owned stores, AG Grid Community, Dockview, Floating UI lookup, TanStack Query, OWIN/net48 HTTP host, existing production ports and actor/capability fences. No switch to framework/AG Grid Enterprise, no new module.
- Preserve WEB4 `web4-v1` canonical 48 corpus blobs (source backend `1c603c6ac57e59a3f7b4bc6ca976b2d531c079aa`), SHA/fingerprint, exact epoch+actor+generation+document identity, local draft raw/lookup/line identity and immutable prepared request. Sales repeated Product/gift allowed, Receipt Product unique, server moving-average inventory/COGS authoritative.
- **Never store access/refresh token, cookie, SQL credential, authorization/capabilities in IndexedDB**. Owner retains short JWT access token in localStorage (known XSS residual); refresh GUID remains HttpOnly cookie. Do not silently change auth/permission model.
- **No auto-retry:** status 404/403/timeout/expired, missing journal and OS crash are **not** rollback evidence. Never re-POST with new operation ID to “fix” UNKNOWN, never use public Get as protected settlement. Same-key user resend remains disabled by default until B01 proof + B02 compatibility/security review + F02 explicit UI acceptance; every action after negative tombstone must be new user intent and fresh baseline.
- Do not reopen WEB1–04 tasks or change legacy Web11/Desktop10 compatibility. Backend CEX remains independently active. Full IIS, production release, Telex/VNI/Narrator and operator tooling are NOT implicitly approved.

## 3. F02 — Terminal-resolution UX and conditional explicit resend (WEB5-02)

**Backend-first absolute gate:** B01 OS-crash/Commit and B02 SQL negative terminal/authorization/versioned resolution tests must PASS and be reviewed, with immutable new corpus/protocol pin. If either is missing, implement safe read-only operator metadata UX only, keep controls disabled and mark conditional subtask BLOCKED (not PASSED).

1. Add a narrow versioned `OperationResolutionPort` in `src/infrastructure/http/` only after reading actual B02 route/DTO. It must enforce Bearer, current session actor/generation, epoch, exact operation ID + freshly recomputed fingerprint from persisted frozen request, expected method/route/target, current module permission, strict Zod schema/size and response integrity. Older WEB4 `operationStatusPort` stays unchanged; no trust in stored digest or user-supplied “committed” flag.
2. Extend `web4MutationRuntime` and typed durable operation repository using an explicit state machine, **without creating a second independent source of truth**. Treat verified COMMITTED with original result as existing positive settlement; COMMITTED with expired result has no usable edit version and stays protected; INDETERMINATE/404/403/timeout stays UNKNOWN. Only exact authorized durable terminal `NOT_EXECUTED`, matched to current live draft checkpoint, can release original operation lock after an atomic IDB/CAS transition. Preserve original raw/lookup/text buffers, clientLineId, changed/not-changed version; never clear an unrelated draft.
3. For safe negative resolution, require user to **review** fresh server document state and capability before any subsequent Save/Post. New action must start with new explicit user intent/operation ID only after the terminal certificate was durably recorded and local ownership/CAS verified. If no current valid Write baseline/version or authority, remain read-only/reconciliation; never invent version. Cross-tab tabs must not independently release or dispatch.
4. A distinct **user-confirmed SAME-KEY resend** of the *unchanged frozen original intent* may be offered **only after B01 proves delayed original vs same-key replay under crash, B02 verifies terminal/expiry and current authorization, and explicit Owner acceptance authorizes that UI gate**. Require destructive-risk warning, one-time click confirmation with module/command/operation ID, original actor/epoch/fingerprint and server status recheck, no auto timer. Recheck no committed/tombstone/revoked/expired or changed data; send *exact identical headers, URL, original body, key and version*, only once; if result lost again keep UNKNOWN. Do not create a fresh key or reuse mutable UI values. Implement fail-closed branch if product is not authorized to enable it.
5. Error/copy: show support ticket correlation and sanitized IDs/epoch, distinguish `Kiểm tra kết quả` (GET), `Thử lại lưu cục bộ` (no HTTP), and conditional `Gửi lại đúng thao tác` (HTTP and disabled by default). For unsupported/corrupt local operation present operator IDs as **unverified metadata only** without exposing content. Never show private data after actor switch or revoked grant.
6. Test six command outcomes, Read-denied Write, Sales Post version/Receipt Post no version, literal decimal/int64, 200-line and raw-IME buffers, quota during negative settlement, malicious valid-looking foreign result, late status, two tab race, expired tombstone, missing negative, rollback vs status404 and default disabled resend. RED→GREEN controlled HTTP/native IndexedDB plus actual port/SQL through approved backend fixture. Production artifact must contain no fake/admin-secret capability.

7. **Positive business-commit case workflow (P1-01):** distinguish original result still available, `COMMITTED` but original Write detail/version unavailable/expired, `INDETERMINATE` and durable `NOT_EXECUTED`. For COMMITTED-result-unavailable, F02/F05 may show an operator-confirmed support ticket/correlation and completion of BUSINESS case, but keep the client intent protected; do **not** silently `SETTLED`, clear an old operation, infer rowversion, duplicate Post or offer new-key retry. A separate optional user-consented **local case/draft archive** (not business delete or editing unlock) requires an Owner-approved policy, matching actor/epoch/operation/CAS, durable minimal ticket link and explicit warning; failure retains UNKNOWN. New edit requires actual fresh authorized server baseline/version, otherwise escalate (including Write-without-Read). Test on both Sales/Receipt after 7-day window, storage abort, another tab and revoked Read.
8. **Client cutover (P1-02):** do not implement a speculative frontend-only version header. If B02 chooses additive compatibility, the old frozen WEB4 write ports stay valid and browser session/UNKNOWN survives new-host deployment. If strict, consume a server-mandated version/mode negotiated and verified on EACH mutation/status; old open/cached tabs fail closed and safely show upgrade/recovery instructions. Changing database epoch on code rollout is prohibited; test old-assets/new-host, new-assets/old-host, both active old tabs and rollback with no duplicate effect.

**Exit:** exact B02 protocol pinned; UX state transition+keyboard/screen reader focus/error behavior pass at current candidate; SQL-proof positive and negative result gates pass. If product resend not independently approved, F02 can be DONE with **resend disabled** and conditional gate explicitly NOT APPROVED; do not label resend PASS.
